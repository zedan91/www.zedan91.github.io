AZOBSS PATCH 706 - FAST PRIVATE R2 TEMPORARY LINK REDIRECT
Date: 31 July 2026
Baseline: Patch 705

Problem fixed
-------------
Creating a private temporary R2 link could feel slow because the backend performed a
blocking HEAD request from Render to the Cloudflare Worker before redirecting the
customer. The old timeout was up to 12 seconds. deploy-server.js also waited for a
Firestore token update before returning the redirect.

Changes
-------
1. R2 signed-token generation remains local and immediate.
2. The default R2 preflight mode is now OFF, so Start Download redirects immediately.
3. Existing AZOBSS_R2_PREFLIGHT_HEAD=1 is treated as BACKGROUND, not blocking.
4. Blocking verification is available only when explicitly configured:
   AZOBSS_R2_PREFLIGHT_MODE=blocking
5. Optional background HEAD timeout reduced from 12 seconds to 3 seconds.
6. deploy-server.js no longer waits for the Firestore token-session update before
   returning the R2 redirect. Persistence continues safely in the background.
7. /api/premium/download-health now reports:
   - r2PreflightMode
   - r2PreflightBlocking

Recommended Render setting
--------------------------
For the fastest flow, either remove AZOBSS_R2_PREFLIGHT_HEAD or set:
AZOBSS_R2_PREFLIGHT_MODE=off

Do not set blocking mode for normal customer downloads. The Cloudflare Worker still
validates the HMAC token and checks the private object when the real download request
arrives.
