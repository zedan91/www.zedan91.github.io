AZOBSS Critical Phone + PA/BM Fix

Fixed issues:
1. Prevented duplicate signup/login submit handlers from both auth scripts running at the same time.
   - azobss-global-auth.js and azobss-firebase-live-likes-sync.js both had auth handlers.
   - Added stopImmediatePropagation so one submit does not get processed twice.

2. Signup now forces Invite Code + Phone to be read again right before Firestore write.
   - phone / phoneNumber are saved from the real signup phone input.
   - inviteCode/memberCode/paMemberCode are saved from the real Invite Code input.

3. If Invite Code is ZX6186, Firestore is forced to save:
   - paBmAccess: true
   - paBmAllowed: true
   - allowPABM: true
   - allowPaBm: true
   - allowPaBmTab: true
   - paBmTabAllowed: true
   - showPaBmTab: true
   - canAccessPaBm: true
   - paAccess: "yes"

4. Login/auth refresh no longer overwrites phone with empty value.
   - It preserves existing phone / phoneNumber.
   - It also uses local signup fallback if Firestore profile was just created.

5. Sticky PA/BM visibility uses the same Firestore PA/BM fields.

- Register with phone and Invite Code: zx6186.
