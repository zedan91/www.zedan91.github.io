AZOBSS (564) - FIRST CLICK AUTO DOWNLOAD FIX
Date: 2026-07-24
Baseline: (563)-AZOBSS-JUPEM-GP-JOB-READY-BEFORE-CART-FIX_20260724.zip

Problem fixed
- On the first Download click, AZOBSS prepared the Lot Kadaster ZIP and then stopped.
- The user had to click Download a second time before the prepared ZIP was downloaded.

Root cause
- After prepare=1 reported ready=true, the frontend entered a waitedForPreparation branch that changed the label back to Download and returned false.
- That return prevented the same click flow from continuing to fetch the finished ZIP.

Changes
1. Remove the early return after Lot Kadaster ZIP preparation completes.
2. Continue immediately from ready=true into the actual file fetch and browser download.
3. Apply the same fix to both shared PA/BM download modules.
4. Bump PA-BM script cache query from v=571 to v=572 so browsers load the patched JavaScript immediately.

Files changed
- assets/js/azobss-global-auth.js
- assets/js/azobss-firebase-live-likes-sync.js
- PA-BM/index.html
- package.json

Deployment
- Upload/deploy the website files to GitHub Pages.
- Render backend redeploy is NOT required for this frontend-only fix.
- Firebase Rules and Render Environment Variables do not need changes.

Expected flow
- First click -> Sedang Proses... -> ZIP becomes ready -> download starts automatically.
- No second click is required.
