AZOBSS PATCH 411 - Subscription Online License Server + Device Transfer

Request:
- Implement the best subscription-code system now.
- Customer may change PC. New PC can sign in and enter the same activation code.
- New PC can transfer the subscription and the old PC becomes revoked.
- Admin needs a way to generate/manage subscription codes.

Backend added:
- POST /api/subscription/verify
  - Online verification for software.
  - Requires activation code + productId + deviceId.
  - 1 activation code = 1 active device.
  - First valid device is auto-bound.
  - Same device verifies normally.
  - Different device returns transfer_required.
  - If confirmTransfer/transfer=true, backend transfers to the new device.
  - Old device becomes invalid/revoked when it verifies online again.
  - Transfer limit: 3 per year.
  - Offline grace value returned: 3 days.
- POST /api/subscription/admin/create-code
  - Admin manual generate activation code.
- GET /api/subscription/admin/list
  - Admin list/search codes.
- POST /api/subscription/admin/reset-device
  - Admin reset device if customer PC is broken.
- POST /api/subscription/admin/revoke
  - Revoke/reactivate activation code.
- POST /api/subscription/admin/extend
  - Extend expiry by days.

Admin Dashboard added:
- New menu: Subscription Codes
- Generate code form.
- Search/list codes.
- Copy code.
- Reset device.
- Revoke/reactivate.
- Extend expiry.

Rules implemented:
- 1 code = 1 active device.
- Transfer allowed 3 times/year.
- Offline grace: 3 days, returned to software.
- Product ID check.
- Optional buyer email/username match check if software sends it.
- Code is stored with activationCodeHash and backed up to Firestore subscriptionCodes.

Subscription plans:
- 1 Month Activation Code — RM29.90
- 3 Months Activation Code — RM69.90 — Save RM19.80
- 12 Months Activation Code — RM239.00 — Save RM119.80

Software verify payload example:
POST https://azobss-backend.onrender.com/api/subscription/verify
{
  "code": "AZOBSS-1M-XXXXXX-XXXXXX-XXXX",
  "productId": "AZSW-372165",
  "deviceId": "DEVICE-ID-HERE",
  "email": "customer@gmail.com",
  "appVersion": "1.0.0"
}

Transfer to new PC:
POST same endpoint with:
{
  "code": "...",
  "productId": "AZSW-372165",
  "deviceId": "NEW-PC-DEVICE-ID",
  "email": "customer@gmail.com",
  "confirmTransfer": true
}

Firebase Rules:
- No frontend Firestore Rules update required for the website UI.
- Backend uses Firebase Admin SDK.
- New Firestore backup collection used by backend: subscriptionCodes.

Render ENV:
- No new ENV required.
- Optional only for extra security:
  AZOBSS_SUBSCRIPTION_HASH_SECRET
  If unset, backend falls back to AZOBSS_DOWNLOAD_HASH_SECRET / ADMIN_KEY.
