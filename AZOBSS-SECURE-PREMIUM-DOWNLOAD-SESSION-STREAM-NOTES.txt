AZOBSS PATCH 373 - SECURE PREMIUM DOWNLOAD SESSION STREAM
Date: 2026-06-26
Baseline: (372)-AZOBSS-PREMIUM-NEVER-EXPIRE-REAL-TOKEN-DISPLAY-FIX_20260625_20260626_002703.zip

Issue fixed:
- Previous POST /api/premium/download/:token incremented usedCount and then redirected to the real downloadLink.
- IDM/download manager could capture the real files.azobss.com .exe URL and redownload/share it outside the one-time token flow.

New secure flow:
1. GET /api/premium/download/:token shows confirmation page only. It does not consume quota.
2. POST /api/premium/download/:token creates ONE short-lived backend download session.
3. Backend returns 303 Location: /api/premium/download-session/:sessionId.
4. GET/HEAD /api/premium/download-session/:sessionId streams the file through backend.
5. Browser/IDM can use Range/resume inside the same session without adding extra usedCount.
6. The real downloadLink/private file URL is never sent as a redirect Location to user/IDM.

Files changed:
- deploy-server.js
  * Added secure download session helpers.
  * Replaced old POST redirect-to-real-file logic.
  * Added /api/premium/download-session/:sessionId.
  * Added /api/premium/download-health.
  * Added HEAD + Range support for IDM.
  * Added CORS headers for Range/If-Range.
- backend/server.js
  * Legacy backend route patched too, so it will not revert to direct redirect if used separately.
- render.yaml
  * Added recommended ENV placeholders for secure download session.
- backend/render.yaml
  * Added recommended ENV placeholders if backend folder is deployed separately.

Recommended Render ENV:
- AZOBSS_DOWNLOAD_HASH_SECRET = random 32+ character secret (required/recommended)
- AZOBSS_DOWNLOAD_SESSION_TTL_MS = 900000
- AZOBSS_PREMIUM_ALLOWED_FILE_HOSTS = files.azobss.com

No Firebase Rules update required:
- premiumDownloadSessions is backend-only.
- Backend uses Admin SDK/local JSON fallback.

Important operational note:
- This patch prevents new token downloads from exposing the real file URL.
- Any old direct URL that is already public, for example https://files.azobss.com/Azobss_SolatTime_Setup_v1.0.exe, can still be opened directly while that object remains public.
- For maximum security after deploy: rename/rotate premium .exe file URL and keep the new source URL only inside backend token/order data. Best future option: private storage/R2/S3 signed backend-only source.
