AZOBSS PATCH 423 - Admin Payment Logs Delete Endpoint Fallback Fix

Issue:
- Payment Logs bulk delete showed browser alert:
  "Invalid backend response"
- This normally means the frontend called:
  POST /api/admin/payment-logs/delete
  but Render backend returned HTML/404/non-JSON.
- Most likely cause: GitHub/frontend was deployed but Render backend was not redeployed after patch 420/422.

Fix:
- azAdminFetchJson now reads raw response text and gives a clear error when backend returns non-JSON.
- For Payment Logs delete specifically, the error now says:
  "Payment Logs delete endpoint belum aktif / belum deploy di Render backend..."
- Added Firebase client fallback:
  - If backend endpoint is not ready, admin page tries to delete matching Firestore docs directly from:
    purchaseLogs
    premiumOrders
  - This fallback depends on Firebase Rules allowing admin delete.
  - It cannot delete local premium-orders.json backup; full cleanup still requires Render backend deploy.
- Backend delete endpoint response now includes:
  patch: 423
  runningFile: deploy-server.js

Expected result:
- If Render backend is deployed: Delete Selected / Clear Pending works through backend.
- If Render backend is not deployed: user sees clearer message and Firestore fallback may still remove records.
- No more vague "Invalid backend response" only.

Based on:
- Patch 422 baseline.

Important:
- Render backend deploy is still required for full premiumOrders/local backup cleanup.
- Firebase Rules no update required for backend route.
- Firebase fallback only works if current Rules already allow admin delete.

Not changed:
- Cart checkout productId fix remains.
- Cart max quantity 1 remains.
- Payment Logs bulk select/delete UI remains.
- Subscription verify/health endpoint remains.
