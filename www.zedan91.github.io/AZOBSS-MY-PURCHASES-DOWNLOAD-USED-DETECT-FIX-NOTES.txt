AZOBSS PATCH 378 - MY PURCHASES DOWNLOAD USED / EXPIRED DETECT FIX

Issue:
- Premium Software/CAD secure download usage is counted inside premiumDownloadTokens when POST /api/premium/download/:token creates a secure download session.
- My Purchases card reads premiumOrders, so it could still show Download 0/1 even after the token was already used.

Fix:
- When a real secure download session is created/reused, backend syncs usage back to premiumOrders:
  downloadCount / usedCount / downloadsUsed
  maxDownload / maxDownloads / downloadLimit
  downloadExpired / downloadActive / downloadStatus
  activeDownloadSessionId / activeDownloadSessionExpiresAt
  lastDownloadedAt / lastDownloadedAtMs
- /api/my-purchases premium meta now reads usedCount/downloadsUsed too, not only downloadCount.
- My Purchases frontend auto-refreshes after opening premium download link, so after user presses Start Download the button updates from Download 0/1 to Downloaded 1/1 or expired/unavailable.

Expected display:
- Paid but not used: Download 0/1
- Used one-time token: Downloaded 1/1
- Time expired before use: Download expired
- Session expired does not expose real files.azobss.com URL.

Firebase Rules:
- No update required. Backend uses Admin SDK/server storage.

Render ENV:
- No new ENV required.
- Existing AZOBSS_DOWNLOAD_SESSION_TTL_MS controls session lifetime.
