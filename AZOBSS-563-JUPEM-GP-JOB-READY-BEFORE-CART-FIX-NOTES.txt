AZOBSS (563) - JUPEM GP JOB READY BEFORE CART FIX

Baseline:
- Built from (562)-AZOBSS-JUPEM-LOT-REGISTRATION-RETRY-FIX_20260724.zip

Root cause fixed:
- JUPEM ArcGIS returns a Job ID while the clipping job may still be Submitted/Executing.
- The previous backend attempted to register that incomplete Job ID into eBiz cart immediately.
- This caused intermittent "JUPEM did not register the selected lot product" failures.

Changes:
1. Poll the JUPEM ArcGIS GP job until esriJobSucceeded before eBiz cart registration.
2. Refresh stale ArcGIS map authentication automatically during status polling.
3. Retry transient cart registration three times after the job succeeds.
4. Accept a successful authenticated JUPEM product-trigger response even when the body is empty/partial.
5. Broaden cart-row parsing when JUPEM moves the delete argument position.
6. Increase background ZIP preparation attempts from 3 to 6.
7. Replace the old permanent "did not register" error with a retryable synchronization state.

Deployment:
- Render backend redeploy is required because deploy-server.js changed.
- No Firebase Rules update is required.
- No new Environment Variables are required.
- Keep JUPEM_EBIZ_USERNAME and JUPEM_EBIZ_PASSWORD configured in Render.

Validation:
- node --check deploy-server.js: PASS
- Old exact popup text removed from executable backend code: PASS
